# dev-agent

Автономный агент-разработчик. Работает с проектом из `../repositories/<имя>`: строит карту проекта,
через дешёвую модель-диспетчер выбирает нужные файлы, просит исполнителя написать патч, применяет его
под защитой, прогоняет линтер и тесты проекта и при ошибках исправляет сам (до 3 раз).

## Запуск

```bash
npm install
cp .env.example .env      # заполнить ключи
npm start                 # выбрать проект и работать в чате
npm test                  # тесты самого агента (node:test, без внешних зависимостей)
```

Команды в чате: `/run` `/stop` `/save` `/index` `/abort` `/redo` `/clear` `/editor` `/push`.
Файлы подтягиваются через `@имя.js`.

## Настройка (`agent.config.json`)

| поле | назначение |
|---|---|
| `llm.dispatcherModel` | модель-диспетчер (выбор файлов, сжатие сессии, HISTORY) |
| `llm.executorModel` | исполнитель (пишет патчи) |
| `llm.cloudFallbacks` | облачные модели, которые пробуются по порядку, если исполнитель упал |
| `llm.fallbackModel` | локальная модель — последняя инстанция и переводчик |
| `llm.ollama` | необязательно: `endpoint`, `num_ctx`, `num_gpu` |
| `llm.defaultProvider` | необязательно: провайдер для моделей с неизвестным именем |
| `workspace.targetProject` | проект по умолчанию (во время работы выбирается в меню) |

Провайдер определяется по имени модели: `qwen/llama/gemma` → Ollama, `deepseek` → DeepSeek,
`claude` → Claude, `gemini` → Gemini.

## Где что лежит

Всё, что агент хранит о проекте, находится в `<проект>/.dev-agent/`: `session.md`, `PROJECT_MAP.md`,
`backups/`. Добавьте `.dev-agent/` в `.gitignore` проекта. Устройство кода — в `ARCHITECTURE.md`.

## Защита

- Патч применяется целиком или не применяется вовсе. Отклоняются: пути вне проекта, `.env*`, `.git`,
  `.dev-agent`, заглушки вида «остальной код без изменений», JS с синтаксической ошибкой,
  файлы, сжавшиеся более чем на 60%.
- `.env` не читается в контекст LLM и не попадает в карту проекта.
- Автоматически выполняются только простые команды (`npm install/ci/test/run`, `git status/diff/log/add/commit`,
  `node --check`). Остальные — только после вашего `y`. Из Telegram такие команды отклоняются.

## Telegram-бот

Задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env`, затем `cd dev-bot && npm install && node dev-bot.js`.
`/list` — проекты, `/p <номер или имя>` — выбрать, любой другой текст — задача агенту.
Проект запоминается по имени, а не по номеру, и до выбора задачи не принимаются.
