# dev-agent

Автономный агент-разработчик. Работает с проектом из `../repositories/<имя>`: строит карту проекта,
оркестратор (Gemini) выбирает нужные файлы и исполнителя, исполнитель пишет патч, агент применяет его
под защитой, прогоняет линтер и тесты проекта и при ошибках исправляет сам (до 3 раз, с эскалацией на модель сильнее).

## Запуск

Рядом с папкой агента должна лежать `../ai-core` (общий пакет `@veroma/ai-core`, github.com/VeRoma/ai-core).

```bash
npm install
cp .env.example .env      # заполнить ключи
npm start                 # выбрать проект и работать в чате
npm test                  # тесты самого агента (node:test, сеть подменяется, ключи не нужны)
```

При старте агент показывает, доступна ли каждая модель из конфига (🟢 / 🟡 нет такой модели / 🔴 провайдер недоступен).

Команды в чате: `/audit [фокус]` `/p <проект>` `/self` `/self-diff [full]` `/run` `/stop` `/save` `/index` `/undo` `/abort` `/redo` `/clear` `/editor` `/push`.
Файлы подтягиваются через `@имя.js` (любой файл проекта, кроме секретов).

Отмена правок агента (откатываются только файлы, которые менял агент; ваши правки в других файлах не трогаются):
- `/undo` — отменить последнюю задачу целиком, со всеми её попытками исправления; память агента сохраняется,
  и он узнаёт об отмене. Повторный `/undo` — предыдущая задача.
- `/abort` — отменить все правки с начала сессии (с последнего `/save`) и стереть память.
- `/redo` — вернуть то, что отменили последним `/undo` или `/abort`.

## Самоулучшение (проект `self`)

Агент может улучшать сам себя, но никогда не правит копию, из которой запущен.

- Выберите `0` / `self` в меню проектов, `/self` или `/p self` в чате, `/p self` в Telegram.
- Целью становится `git worktree` этого репозитория в соседней папке `../dev-agent-self` на ветке `self-improve`.
  Агент правит и тестирует только её; `node_modules` подключаются ссылкой из рабочей копии.
- Пока в `self-improve` нет своих коммитов, worktree автоматически подтягивается до текущей версии агента.
  Ветку с неслитыми правками агент не трогает.
- В режиме self проект не запускается (`/run`, `restartServer`): это была бы копия самого агента.
- `/self-diff` (из любого проекта) показывает, что агент изменил: его коммиты, незакоммиченные правки и новые файлы
  относительно точки ответвления от рабочей версии, — и запускает тесты worktree. `/self-diff full` — полный diff.
- Новая версия попадает в рабочую копию только вручную: `/self-diff` подсказывает команды (зафиксировать правки,
  `git merge self-improve`, тег). Слияние, тег и push агент сам не выполнит — они требуют подтверждения.
- Защита путей и команд живёт в пакете `@veroma/ai-core`, а не в коде агента: правя себя, агент не может её ослабить.

Вернуться к обычному проекту: `/p <номер или имя>`.

## Оценка качества (`npm run eval`)

Набор контрольных задач, чтобы любую правку агента (свою или из `self`) было видно по цифрам.

- `npm run eval` — все задачи; `npm run eval -- big-file-surgical add-median` — выбранные;
  `--keep` — не удалять проекты задач (путь печатается), `--timeout=<сек>` — лимит на задачу (по умолчанию 600).
- Каждая задача — маленький проект во временной папке системы (не в `../repositories`), агент работает с ним
  в отдельном процессе с настоящими моделями из `agent.config.json`. **Тратит токены.**
- После агента запускаются скрытые тесты (агент их не видит) и проверки: секрет не в коде, тест не подогнан,
  в большом файле правка точечная, на вопрос — без правок и т. д.
- Итог: прошла ли задача, что агент сам считает исходом, вызовы исполнителя и исправления, уровни (`fast→pro`),
  токены, стоимость (по `llm.pricing`), время; сравнение с прошлым прогоном (↑/↓).
- Логи и результаты — в `evals/results/` (в git не попадают). Задачи — в `evals/tasks.js`; у каждой есть эталонное
  решение, и `npm test` проверяет, что проверки на нём проходят, а на нетронутом проекте — нет.
- Для self: запуск `npm run eval` в `../dev-agent-self` оценивает версию агента из worktree.

## Как выбирается модель

1. Оркестратор (`llm.orchestratorModel`) читает задачу и карту проекта, выбирает файлы и исполнителя:
   `fast` (DeepSeek — рутина), `pro` (Gemini 4 Argon — большие файлы ⚠️ [GOD FILE] и несколько модулей),
   `arch` (Claude — безопасность, конкурентность, сложные алгоритмы).
2. Тег в задаче перекрывает выбор: `@ds` → fast, `@ge` / `@gemini` → pro, `@claude` / `@cl` → arch.
3. Эскалация: после 2 неудач подряд на одном уровне (патч отклонён защитой, упали проверки, невалидный ответ)
   следующая попытка уходит уровнем выше: `fast → pro → arch`. Уровень, заданный тегом, не повышается.
4. `/audit` никогда не уходит на `fast`. Исполнитель получает исходную задачу и план оркестратора;
   при подгрузке файлов по `@` продолжает тот же исполнитель.
5. Если оркестратор недоступен — `fast` с файлами из `@`.

После каждой задачи выводится расход токенов по ролям (оркестратор, исполнитель, исправления, перевод).
Чтобы видеть стоимость, задайте цены за 1M токенов в `llm.pricing`:
`"pricing": { "deepseek-flash": { "input": 0.0, "output": 0.0 } }` (подставьте актуальные цены провайдера).

## Настройка (`agent.config.json`)

| поле | назначение |
|---|---|
| `llm.orchestratorModel` | оркестратор (выбор файлов и исполнителя) |
| `llm.tiers.local` | локальная модель: перевод RU↔EN, сжатие сессии, HISTORY |
| `llm.tiers.fast` / `pro` / `arch` | исполнители по уровням |
| `llm.cloudFallbacks` | облачные модели, которые пробуются по порядку, если модель уровня упала |
| `llm.pricing` | необязательно: цены для сводки расхода |
| `llm.ollama` | необязательно: `endpoint`, `num_ctx` (по умолчанию 8192), `num_gpu` (не задан — Ollama сама грузит в GPU сколько влезет; `0` — только CPU) |
| `llm.defaultProvider` | необязательно: провайдер для моделей с неизвестным именем |

Проект в конфиге не задаётся: он выбирается в меню при старте (или `AUTO_PROJECT`, или `/p` во время работы).

Провайдер определяется по имени модели: `qwen/llama/gemma` → Ollama, `deepseek` → DeepSeek,
`claude` → Claude, `gemini` → Gemini.

## Где что лежит

Всё, что агент хранит о проекте, находится в `<проект>/.dev-agent/`: `session.md`, `PROJECT_MAP.md`,
`backups/`, `agent.lock`. Добавьте `.dev-agent/` в `.gitignore` проекта. Устройство кода — в `ARCHITECTURE.md`.

## Защита

Проверки путей, патчей и команд — общие с meta-agent, из `@veroma/ai-core/safety`.

- Существующий файл исполнитель правит точечно: пары «найти → заменить» (`edits`), каждый фрагмент должен
  встречаться в файле ровно один раз. Агент сам собирает из них полный файл, и все проверки ниже видят его целиком.
  Новые файлы — полным текстом (`content`).
- Патч применяется целиком или не применяется вовсе. Отклоняются: пути вне проекта, `.env*` и другие секреты,
  `.git`, `.dev-agent`, заглушки вида «остальной код без изменений», JS с синтаксической ошибкой,
  файлы, сжавшиеся более чем на 60%.
- Секреты (`.env*`, ключи, `credentials.*`) не читаются в контекст LLM и не попадают в карту проекта.
- Автоматически выполняются только простые команды (`npm install/ci/test`, `npm run test|lint|build|check`,
  `git status/diff/log/add/commit`, `node --check`, `node --test`). Остальные — только после вашего `y`.
  Из Telegram такие команды отклоняются.
- Авто-починка после `/run` — только при настоящем падении (ненулевой код выхода, `[nodemon] app crashed`,
  сбой старта Spring Boot) и после вашего согласия.
- С одним проектом одновременно работает только один агент (`.dev-agent/agent.lock`).

## Telegram-бот

Задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env`, затем `cd dev-bot && npm install && node dev-bot.js`.

- `/list` — проекты (`[0] self` — сам агент), `/p <номер, имя или self>` — выбрать, `/help` — подсказка.
- Любой текст — задача агенту. Из команд агента доступны `/audit`, `/self-diff` (работает и без выбранного проекта), `/index`;
  остальные (`/run`, `/editor`, `/abort`...) без терминала не имеют смысла и отклоняются.
- Проект запоминается по имени, а не по номеру, и до выбора задачи не принимаются. Одна задача за раз.
- Правила выбора проекта — те же, что у агента (общий код `src/project/projects.js`).
