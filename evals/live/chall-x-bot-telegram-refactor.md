# Живая задача: реорганизация TelegramBotService (chall-x-bot)

Сравнение «Claude Code против dev-agent» на одной задаче от одного коммита.
Не входит в `npm run eval`: проект настоящий, Java, проверка — `mvnw test` и ручной смоук.

## Подготовка

- Исходное состояние — коммит `df2b226` в `chall-x-bot` (сделан 2026-11-03 перед задачей).
- Claude Code сделал шаги 0–3 прямо в `main` (`54b502d..804e943`).
- dev-agent: отдельная копия от того же исходного коммита, чтобы правки не смешивались:
  ```
  cd ../repositories/chall-x-bot
  git worktree add ../chall-x-bot-agent -b refactor-agent df2b226
  ```
  В копии нет `.dev-agent/` и `.env` (они не в git). Для одинаковых условий скопировать
  `.dev-agent/session.md` (в нём прошлый аудит) или убрать ссылку на него из задачи — у обоих одинаково.
- Агенту — тег `@claude` хотя бы для плана (у Claude Code — Opus, иначе сравниваем ещё и выбор оркестратора).
- ⚠️ До шага 0 плана не запускать `mvn test` с загруженным `.env`: `ChallxbotApplicationTests` подключится
  к рабочей БД и зарегистрирует настоящего бота с тем же токеном.

## Текст задачи (одинаковый для обоих)

> Нужно реорганизовать `backend/src/main/java/com/challxbot/service/TelegramBotService.java` (~1370 строк).
> Сейчас это фасад + контроллер + презентер в одном классе: транспорт, роутинг команд и callback-ов,
> FSM (`UserState`), квиз-сессии и UI-тексты сцеплены.
>
> **Сначала только план, без правок кода.** Код — после моего одобрения.
>
> Контекст: в `.dev-agent/session.md` (примерно строки 430–600) есть прошлый аудит и план по этапам.
> Сверь его с текущим кодом: что уже сделано (например, `SrsCalculator` вынесен и покрыт тестом),
> что устарело, с чем не согласен. Не доверяй ему — проверяй по коду.
>
> Ограничения:
> - Поведение бота не меняется (behavior-preserving). Если для шага нужны характеризационные тесты — сначала они.
> - Маленькие шаги; после каждого — компиляция и `mvn test` зелёные; каждый шаг — отдельный коммит.
> - Схему БД и сущности `User`/`AppUser` не трогать без отдельного согласования.
> - Не трогать `.dev-agent/` и `.env*`.
>
> В плане: на какие классы делить и почему, порядок шагов, риск каждого шага, как проверяем, что ничего не сломалось.

## Перекрёстная проверка (одинаковые тесты для обоих)

Каждый пишет свои тесты в рамках задачи, поэтому в конце:
- характеризационные тесты Claude Code (`TelegramBotServiceCharacterizationTest`, коммит `0ce9ed7`) прогоняются
  на коде агента после его шагов 0–3, и наоборот — тесты агента на коде Claude Code;
- разрешено менять только сборку бота в тесте (конструктор / зависимости), проверки — никогда;
- красный чужой тест = изменилось поведение (или тест опирается на внутренности — разобрать вручную).

Агент запускается после пункта 2 дорожной карты (точечные правки): текст задачи и условия те же, меняется
только версия агента — она фиксируется в результатах (коммит dev-agent).
