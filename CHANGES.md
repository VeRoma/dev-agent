# Что изменено

## 2026-11-03: точечные правки вместо целых файлов

- Исполнитель правит существующий файл парами `{ search, replace }` (`edits`) вместо полного текста.
  Каждый `search` должен встретиться ровно один раз (иначе патч отклонён с понятной причиной и модель повторяет),
  переводы строк файла (CRLF) сохраняются. Из правок собирается полный файл — защиты ai-core проверяют его целиком.
  Eval: `big-file-surgical` — 418 токенов на выходе вместо 3.0k, $0.017 вместо $0.044, 11 с вместо 69 с;
  весь прогон 8.9k выходных токенов вместо 12.6k.
- `@файл` теперь находит любой разрешённый файл проекта, а не только из карты: раньше `@.gitignore` не подгружался,
  хотя промпт требует проверить `.gitignore` перед созданием `.env` (агент молча останавливался в режиме chat).

## 2026-11-03: новая видеокарта и модели Gemini

- Локальная модель — `qwen2.5-coder:14b` на GPU (RTX 4080 SUPER 16 ГБ). ai-core 1.4.1 больше не шлёт в Ollama
  `num_gpu: 0` (это принудительно включало CPU): без `llm.ollama.num_gpu` Ollama сама грузит модель в GPU.
  Контекст остаётся 8192: с ним модель уже занимает ~13.6 из 16 ГБ.
- Оркестратор и `pro` — `gemini-4-argon` (у `gemini-3.1-pro-preview` лимит 25 запросов/мин и 250/день, а оркестратор
  вызывается на каждую задачу). Оркестратору — сильная модель: ответ у него короткий, это ~$0.005 за задачу. `gemini-2.5-pro` убран из запасных: Google его выводит.
- Сбой Google 2026-11-03 (503 «перегружена» у argon, 3.8-flash, 3.1-pro): каждый вызов тратил три пустые попытки,
  а работающий Claude стоял в запасных последним. Теперь Claude — второй в `cloudFallbacks` (сразу после argon),
  а ai-core 1.4.2 на 5 минут переносит модель, ответившую 503/529, в конец цепочки (`llm.unavailableCooldownMs`).
  Совсем не выбрасывает: если перегружены все, их всё равно пробуют. Память — на процесс (в eval — на задачу).
- Цены в `llm.pricing` сверены со страницей Google 2026-11-03. ⚠️ Акционные: `gemini-4-argon` дорожает вдвое
  с 2026-12-01, `gemini-3.8-flash` — с 2027-01-01.

## 2026-11-02: оценка качества агента

- `npm run eval`: 9 контрольных задач (баг по описанию, функция с тестами, починка без подгонки теста, секрет,
  отказ от удаления `.env`/`.git`, точечная правка в большом файле, переименование, вопрос без правок,
  баг по симптому). Скрытые тесты, метрики (исход, исправления, эскалации, токены, $, время), сравнение с прошлым прогоном.
- `npm test` проверяет сами проверки: каждая падает на нетронутом проекте и проходит на эталонном решении.
- Исправлено: если агент работал под `node --test`, тесты целевого проекта «проходили» даже при падении
  (`NODE_TEST_CONTEXT` превращал вложенный `node --test` в подтест с кодом 0). Тесты проекта теперь запускаются без неё.
- `llm.pricing`: цены Gemini 3.1 Pro и 2.5 Pro (Global, ≤200K).

## 2026-11-02: после живой проверки

- Тесты проекта после патча запускаются один раз: `npm test` / `node --test` из ответа модели пропускаются,
  если правились файлы (их и так запускает проверка). Промпт просит модель такие команды не добавлять.
- `exit`, смена проекта и рестарт больше не пишут «Нет запущенных процессов»; предупреждение — только на `/stop`.
- `workspace.targetProject` убран из конфига: проект выбирается только в меню / `AUTO_PROJECT` / `/p`.
  Без выбранного проекта пути состояния не вычисляются (ошибка вместо записи в проект по умолчанию).
  Раньше `npm test` агента дописывал строки в `session.md` проекта из конфига.
- Папки проектов без доступа (`EPERM` / `EACCES`, например junction в защищённую папку) больше не пропадают
  из меню молча: показываются как «⛔ имя — нет доступа» без номера (нумерация остальных не сдвигается),
  выбрать их нельзя ни в терминале, ни через `AUTO_PROJECT`, `/p` или бота — с понятной причиной.

## 2026-11-02: dev-agent «два в одном» — meta-agent влит сюда

meta-agent ([архив](https://github.com/VeRoma/meta-agent)) больше не нужен: надзор за самим агентом — проект `self`.

### Модели и стоимость
- Оркестратор (Gemini) на каждую задачу выбирает файлы и исполнителя: `fast` / `pro` / `arch`. Заменил локальный диспетчер.
  Пути, которых нет в карте проекта, отбрасываются; исполнитель получает исходную задачу и план оркестратора.
- Теги `@ds` / `@ge` / `@claude` перекрывают выбор; уровень сохраняется при авто-подгрузке файлов.
- Эскалация: 2 неудачи подряд на уровне → следующая попытка уровнем выше (`fast → pro → arch`).
- Учёт токенов по каждому вызову и сводка после задачи; стоимость — если заданы цены в `llm.pricing`.
- Проверка доступности моделей при старте. В конфиге были модели, которых у провайдеров уже нет
  (`deepseek-chat`, `gemini-3-pro-preview`, `claude-sonnet-4-5`) — заменены проверенными.
- `/audit [фокус]` — полный аудит, никогда на `fast`. Файлы > 300 строк помечены в карте как ⚠️ [GOD FILE].

### Самоулучшение
- Проект `self` (меню `0`, `/self`, `/p self`): агент правит `git worktree` своего репозитория в `../dev-agent-self`
  на ветке `self-improve`, рабочую копию не трогает; проект в этом режиме не запускается.
- `/self-diff [full]`: правки агента от точки ответвления, тесты worktree, команды для ручного выпуска.
  Слияние, тег, push — только вручную.

### Надёжность и безопасность
- Защита путей, патчей и команд — общая с ai-core (`@veroma/ai-core/safety`): агент не может ослабить её, правя себя.
  `$` / `%` в командах и `npm run <любой скрипт>` требуют подтверждения.
- Команды от модели вообще не выполнялись (неверный вызов `runCommands`) — исправлено, исход пишется в сессию.
- Авто-починка после `/run` — только при настоящем падении и после согласия; весь ввод — через один обработчик
  (ответ «y» на подтверждение больше не уходит агенту как задача); одна задача за раз.
- Один агент на проект (`.dev-agent/agent.lock`); задача из Telegram — через окружение процесса, не через общий файл.
- Telegram-бот не запускался (`"type": "commonjs"` при ESM-коде) — исправлено. В боте: `/p self`, `/audit`, `/self-diff`, `/index`.
- Один адаптер ai-core (`src/llm/index.js`) читает общий конфиг; старый `core/llm.js` читал свой и мимо тестов.
- Комментарии в коде — на английском (экономия токенов модели).
