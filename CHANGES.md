# Что изменено

## 2026-11-04: нет денег у провайдера — задача останавливается сразу

- На шаге 9 эксперимента с chall-x-bot у Gemini кончилась предоплата (402), а у Claude — баланс. Агент ~40 раз
  перебрал цепочку запасных моделей, а Claude 4 раза подряд получил тот же обрезанный по max_tokens ответ:
  ≈ $1.40 впустую. ai-core 1.6.0: провайдер без денег пропускается целиком на 10 минут, модель, обрезанная лимитом
  ответа, — тоже; если пропущены все, ошибка `NO_MODELS_AVAILABLE`. Агент на ней не делает ни повтор JSON, ни
  попыток исправления, а сразу сообщает причину.
- В отчёт для модели о падении тестов идут только отчёты surefire текущего прогона: раньше туда попал старый
  отчёт другого тестового класса.

## 2026-11-03: сжатие сессии не теряет план

- Сессия длиннее 150k символов раньше целиком сжималась локальной моделью в 1500 символов. Но у локальной модели
  окно 8192 токена: ~40k токенов истории молча обрезались, и согласованный план (15 шагов на chall-x-bot) пропал бы.
  Теперь последние ~50k символов остаются дословно (граница — по ходу разработчика), а старую часть сжимает облачный
  `fast`-уровень с требованием сохранить каждый шаг плана со статусом, решения разработчика и найденные факты.
  Если сжатие не удалось, сессия остаётся как есть.

## 2026-11-03: тесты Java/Maven и окружение без секретов агента

- После патча агент сам запускает `mvnw test` (или `mvn test`) в Maven-модуле изменённого файла (ближайший `pom.xml`)
  и при падении исправляет код, как с `npm test`. В отчёт для модели идут строки `[ERROR]`, итоги тестов и тексты
  ассертов из `target/surefire-reports`. Раньше Java-проект после патча вообще не проверялся («нет скрипта test»),
  и в эксперименте на chall-x-bot человек трижды запускал тесты вручную. `mvnw test` из ответа модели не дублируется.
- ai-core 1.5.0 `projectChildEnv`: тесты, команды, линтер и `/run` проекта запускаются без секретов агента
  (ключи LLM, токен его Telegram-бота, `*_TOKEN`, `*_KEY`, `*PASSWORD*`, `DATABASE_URL`...). Раньше они наследовали
  `process.env` агента с его `.env`: chall-x-bot читает `TELEGRAM_BOT_TOKEN` и мог поднять бота на токене dev-бота.

## 2026-11-03: после живой задачи на chall-x-bot (сравнение с Claude Code)

итог — `evals/live/chall-x-bot-telegram-refactor.md`. Исправлено то, из-за чего пришлось вмешиваться:

## 2026-11-03: Claude больше не теряет ответ на размышлениях

- ai-core 1.4.3: лимит ответа Claude поднят с 8000 до 16000 токенов (таймаут 10 мин). На большой задаче
  Sonnet 5.5 тратил все 8000 на размышления и не писал ответ; агент видел «Empty model response» и уходил в запасные.
  Теперь обрезка по `max_tokens` — понятная ошибка, а потраченные токены видны в сводке. Лимит — `llm.claude.maxTokens`.
- Цена `claude-sonnet-5-5` в `llm.pricing`: $2 / $10 за 1M (официальные цены Anthropic).

## 2026-11-03: /undo — отмена последней задачи

- `/undo` отменяет только последнюю задачу агента (со всеми попытками исправления), а не всю сессию, как `/abort`.
  Память сохраняется, в сессию пишется, что правки отменены. `/redo` возвращает отменённое.
  Журнал задач — `.dev-agent/backups/tasks.json` поверх прежних бэкапов (git checkpoints не понадобились:
  откат файлов агента, включая созданные и удалённые, уже был).
- Исправлено: `/redo` после `/abort` не удалял снова файл, который агент удалил в задаче.

## 2026-11-03: точечные правки вместо целых файлов

- Исполнитель правит существующий файл парами `{ search, replace }` (`edits`) вместо полного текста.
  Каждый `search` должен встретиться ровно один раз (иначе патч отклонён с понятной причиной и модель повторяет),
  переводы строк файла (CRLF) сохраняются. Из правок собирается полный файл — защиты ai-core проверяют его целиком.
  Eval: `big-file-surgical` — 418 токенов на выходе вместо 3.0k, $0.017 вместо $0.044, 11 с вместо 69 с;
  весь прогон 8.9k выходных токенов вместо 12.6k.
- `@файл` теперь находит любой разрешённый файл проекта, а не только из карты: раньше `@.gitignore` не подгружался,
  хотя промпт требует проверить `.gitignore` перед созданием `.env` (агент молча останавливался в режиме chat).

  Без выбранного проекта пути состояния не вычисляются (ошибка вместо записи в проект по умолчанию).
  Раньше `npm test` агента дописывал строки в `session.md` проекта из конфига.

  выбрать их нельзя ни в терминале, ни через `AUTO_PROJECT`, `/p` или бота — с понятной причиной.

## 2026-11-02: dev-agent «два в одном» — meta-agent влит сюда

meta-agent ([архив](https://github.com/VeRoma/meta-agent)) больше не нужен: надзор за самим агентом — проект `self`.

### Модели и стоимость
- Оркестратор (Gemini) на каждую задачу выбирает файлы и исполнителя: `fast` / `pro` / `arch`. Заменил локальный диспетчер.
  Пути, которых нет в карте проекта, отбрасываются; исполнитель получает исходную задачу и план оркестратора.
- Теги `@ds` / `@ge` / `@claude` перекрывают выбор; уровень сохраняется при авто-подгрузке файлов.
- Эскалация: 2 неудачи подряд на уровне → следующая попытка уровнем выше (`fast → pro → arch`).
- Учёт токенов по каждому вызову и сводка после задачи; стоимость — если заданы цены в `llm.pricing`.
- Проверка доступности моделей при старте. В конфиге были модели, которых у провайдеров уже нет
  (`deepseek-chat`, `gemini-3-pro-preview`, `claude-sonnet-4-5`) — заменены проверенными.
- `/audit [фокус]` — полный аудит, никогда на `fast`. Файлы > 300 строк помечены в карте как ⚠️ [GOD FILE].

### Самоулучшение
- Проект `self` (меню `0`, `/self`, `/p self`): агент правит `git worktree` своего репозитория в `../dev-agent-self`
  на ветке `self-improve`, рабочую копию не трогает; проект в этом режиме не запускается.
- `/self-diff [full]`: правки агента от точки ответвления, тесты worktree, команды для ручного выпуска.
  Слияние, тег, push — только вручную.

### Надёжность и безопасность
- Защита путей, патчей и команд — общая с ai-core (`@veroma/ai-core/safety`): агент не может ослабить её, правя себя.
  `$` / `%` в командах и `npm run <любой скрипт>` требуют подтверждения.
- Команды от модели вообще не выполнялись (неверный вызов `runCommands`) — исправлено, исход пишется в сессию.
- Авто-починка после `/run` — только при настоящем падении и после согласия; весь ввод — через один обработчик
  (ответ «y» на подтверждение больше не уходит агенту как задача); одна задача за раз.
- Один агент на проект (`.dev-agent/agent.lock`); задача из Telegram — через окружение процесса, не через общий файл.
- Telegram-бот не запускался (`"type": "commonjs"` при ESM-коде) — исправлено. В боте: `/p self`, `/audit`, `/self-diff`, `/index`.
- Один адаптер ai-core (`src/llm/index.js`) читает общий конфиг; старый `core/llm.js` читал свой и мимо тестов.
- Комментарии в коде — на английском (экономия токенов модели).
